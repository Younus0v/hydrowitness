The technology, and its limits.

Read-only by design, built from cheap parts, and tested on a simulated plant. Below is how it works inside, then what we tested and what we haven't.

Data flows one way: into HydroWitness.

SCADA values reach the server through a small read-only adapter. Nothing in HydroWitness has a path back to a pump, valve or controller.

Seven rules for catching a lying screen.

Each rule asks whether the numbers on the screen could all be true at once.

  • Tank mass balance. The change in the tank level should match the water going in and out.
  • Pump, flow and tank agreement. A pump that is running should show flow, and the tank should respond.
  • Level and pressure move together. The two readings should not part ways.
  • Physically possible rates. A tank cannot fill or drain faster than the plant allows.
  • Command, then response. When something is commanded, the equipment should answer.
  • Frozen data. Real measurements wobble; a value that stops changing for too long is suspect.
  • Repeated identical sequence. A replayed recording repeats exactly; real data practically never does.

Witnesses are weighed, not just counted.

Amber starts at 1 point and red at 3. An operator who reads the pump themselves is enough for red on their own.

Customers can reach amber alone and never red alone. Red latches: once reached, it stays until a person clears it.

Beside the light, the dashboard lists four plain checks: record integrity, evidence freshness, source agreement and sensor health. They explain the light. They are not a separate score.

Built so a bad actor can't make it lie too.

Signed node messages

Every Witness Node report is signed with that device's own secret (HMAC-SHA256) and carries a counter, so a copied or replayed message is rejected.

Tamper-evident log

Each log record holds the SHA-256 fingerprint of the one before it, so an edited, removed or reordered record breaks the chain and the dashboard says where. Replacing the whole log is only caught if a copy of the latest fingerprint is kept elsewhere. A one-click backup helps with that; sending it to an outside channel automatically is not connected yet.

Private by default

The dashboard needs an access token, the server's secrets never appear in any response, and alerts go only to a private channel, never a public one. If that channel can't be reached, the alert waits and is tried again, and the dashboard says so.

Cheap on purpose.

The only hardware is the Witness Node, and it has no pressure sensor. It listens to the pump instead of measuring the pipe.

The parts are all off-the-shelf. The firmware's signal processing was tested against synthetic pumps on a normal computer; it has not yet run on a real ESP32.

  • ESP32 board: the brain and the Wi-Fi.
  • MPU6050 accelerometer: vibration.
  • INMP441 microphone: sound.
  • A button, three lights and a buzzer: calibration and local status.

What we tested, and what we haven't.

Everything below ran on a simulated plant and simulated Witness Nodes. We say so up front because a simulation shows that the software behaves as designed. It doesn't show how a real pump sounds.

With the forgery, red happens when a person reads the pump. With the hidden valve, only customer calls notice it, and customer reports can't turn the light red on their own, so a flood of calls can't be used to fake an emergency.

Also tested

  • 319 automated tests pass, covering the clock, the rules, the trust light, message signing, the log and the dashboard.
  • The clock was checked against the EPANET hydraulic simulator on 310 randomized systems. Its worst case was never later than the true time in normal conditions. If real demand is far above the configured peak, it can be late (8 of 40 stress cases), so the dashboard states the demand it assumes.
  • With the alert channel switched off, hung and then brought back, the server stayed responsive, kept the alert waiting, and sent it, marked as late, once the channel returned. The Emergency view opens by itself while an alert is waiting or the server can't be reached.
  • On a healthy simulated plant: 0 false amber and 0 false red over 10 site-days, while pumps really started or stopped 33 times.

Not proven yet

  • Whether a real pump shakes and sounds different enough, on and off, to be told apart. That needs the hardware test.
  • The Witness Node firmware has been tested on a computer and compiles for the ESP32, but it has not run on a real board yet.
  • There is no connection to a real SCADA system yet, and no utility has used it.
  • A careful forgery only turns red with a person's reading, and a hidden valve stays amber.
  • The Emergency view has not been used in a real outage. If the plant's own network goes down, a Witness Node can't report and does not save its readings for later.
